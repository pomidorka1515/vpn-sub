# Async watcher (phase 8)  
  
`AsyncBWatch` is composed after core recovery and before HTTP readiness. It owns named interval tasks and a separate per-kind daily retry loop. Defaults remain 15/120/300/7200/86400 seconds, with delay after completion, UTC monthly reset, and linear hourly snapshot retry capped at one day. Job exceptions are logged; cancellation propagates. Repeated close drains scheduled tasks safely. Disabled background startup exposes persisted snapshot failure status without seeding or scheduling.  
  
Public watcher jobs serialize against their scheduled equivalents. User quota decisions, recovery notices, usage commits, monthly resets, and snapshot commits use the core mutation coordinator. Limits and expiry are re-read under account ownership; panel reads happen outside short in-memory updates. Usage and snapshot baselines advance only after successful repository acknowledgement. Required main/whitelist reads finish before either side is committed. Counter regressions retain the previous baseline. Reconcile uses the core's coordinated recovery-aware background operation.  
  
`AsyncNotifier` accepts awaitable language and delivery functions. The watcher reads markers, sends, and persists accepted markers inside an owned account mutation; failed sends leave markers absent. Recovery and terminal notices share the same account coordination. Caller cancellation can detach a critical operation, which the runtime mutation registry drains before closing dependencies. Telegram delivery accepted immediately before a process crash or persistence failure can still be duplicated on restart; existing markers do not provide an external exactly-once journal.  
  
The watcher accepts injected notice/admin channels. Production bot wiring awaits phase 9's AsyncTeleBot conversion; no synchronous Telegram call is introduced into the event loop. The synchronous watcher and notifier remain staged for retirement in phase 12. HTTP snapshot status reads a detached in-memory failure summary loaded at startup and updated by snapshot attempts. Host collection runs through bounded metrics offload.
